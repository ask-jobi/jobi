## MODIFIED Requirements
### Requirement: Section and Block ID Generation

The system MUST generate unique IDs for sections and blocks using `nanoid` when creating new resumes.

#### Scenario: Empty resume has section IDs

- **WHEN** `createEmptyResumeRecord` is called
- **THEN** each section MUST have a unique `id` generated by `nanoid`
- **AND** The section `id` MUST be different from other sections

```typescript
import { nanoid } from "nanoid"

const emptyResumeData: ResumeData = {
  sectionOrder: ['education', 'employment', 'research', 'projects', 'publications', 'awards', 'certifications', 'skills'],
  personalInfo: { id: nanoid(), firstName: "", ... },
  education: { id: nanoid(), title: "Education History", order: 0, blocks: [] },
  employment: { id: nanoid(), title: "Employment History", order: 1, blocks: [] },
  skills: { id: nanoid(), title: "Skills", order: 2, blocks: [] }
}
```

#### Scenario: Optional sections have IDs

- **WHEN** an empty resume is created
- **THEN** optional sections (research, projects, publications, awards, certifications) MUST have their own unique `id`
- **AND** Each optional section MUST be included in `sectionOrder`

### Requirement: Default sectionOrder

New resumes MUST have a default `sectionOrder` array defining the display sequence.

#### Scenario: Default section order is applied

- **WHEN** an empty resume is created
- **THEN** the system MUST set `sectionOrder` to `['education', 'employment', 'research', 'projects', 'publications', 'awards', 'certifications', 'skills']`

### Requirement: Modification by Section and Block ID

Resume modification operations MUST locate and update data by section `id` and block `id`, not by index.

#### Scenario: Find section by ID

- **WHEN** modifying a resume section
- **THEN** the system MUST locate the section by its `id` field
- **AND** The section key in ResumeData MAY change, but the `id` remains constant

#### Scenario: Find block by ID

- **WHEN** modifying a block within a section
- **THEN** the system MUST locate the block by its `id` field within `blocks` array
- **AND** Block order changes MUST NOT affect ID-based identification

```typescript
// Find section by ID
function findSectionById(resume: ResumeData, sectionId: string): SectionBlock | undefined {
  const sectionKey = resume.sectionOrder.find(key => {
    const section = resume[key as keyof ResumeData] as SectionBlock
    return section?.id === sectionId
  })
  return sectionKey ? resume[sectionKey as keyof ResumeData] as SectionBlock : undefined
}

// Find block by ID
function findBlockById(section: SectionBlock, blockId: string) {
  return section.blocks.find(block => block.id === blockId)
}
```

## ADDED Requirements
### Requirement: Section Rendering Order

Resume sections MUST be rendered according to the `sectionOrder` array sequence.

#### Scenario: Sections display in sectionOrder sequence

- **WHEN** a resume is displayed in the editor
- **THEN** sections MUST appear in the order defined by `sectionOrder`

#### Scenario: Drag and drop updates sectionOrder

- **WHEN** a user reorders sections via drag and drop
- **THEN** the `sectionOrder` array MUST be updated to reflect the new order
- **AND** Section positions MUST persist when saved
